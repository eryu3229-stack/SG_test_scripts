## 功率计归零（Zeroing）等待时间修复

- 现象：最大功率测试里归零几乎瞬间返回，用户对照 NRP40P 官方软件（数秒）。
- 根因：`instruments/power_meter.py::zero()` 只 `write("CALibration:ZERO:AUTO ONCE")` 就打印"归零完成"。
  pyvisa 的 `write()` 发送即返回，不会等归零结束；也没查归零结果。
- 依据（R&S NRPxS(N) 用户手册 1177.5079.02 ─ 26，本地 `D:\chrome download\NRPxSN_UserManual_en_26.pdf`，195 页）：
  - p128 `CALibration<Channel>:ZERO:AUTO <state>`：
    - 归零前必须关闭所有测试信号，否则归零报错
    - 归零期间命令为**同步**命令，禁止任何查询/设置，通信可能超时
    - 归零后查**静态**错误队列 `SYSTem:SERRor?`：`0`=成功，`-240`=归零失败
  - p129：`ONCE` 为唯一有效参数；`OFF` 是"无归零进行中"的查询返回值；示例 `*CLS` + `CAL1:ZERO:AUTO ONCE`，原文 "Performs zeroing. Takes several seconds."
  - p145：`SYSTem:SERRor?` = 查询下一个静态错误（与 `SYSTem:ERRor[:NEXT]?` 的 SCPI 通信错误队列是两回事）
- 修复：`zero(wait_s=None)` 改为 `*CLS` → `CAL:ZERO:AUTO ONCE` → 显式 `time.sleep(wait_s)` → 查 `SYST:SERRor?`，非 0 抛异常。
  - 默认等待常量 `PowerMeter.DEFAULT_ZERO_WAIT_S = 8.0`；可经构造参数 `zero_wait_s=` 或调用参数 `wait_s=` 覆盖。
  - 只等待、不轮询 `CAL:ZERO:AUTO?`：手册明确归零期间禁止查询，轮询有超时风险。
  - 未改动调用方（`run_scripts/max_power_test.py`、`run_scripts/power_sweep.py`、`run_scripts/gui.py` 各调用一次 `zero()`）。

## 排查"杂散程序数据丢失"（用户提问）

结论：**程序没有丢数据**。用户看到的"变少"是外部清洗产物 `output/spurious_stream_merged_clean_20260913.csv`。

关键证据：
- 该文件名是 `.csv`，实际是 XLSX（PK zip 容器，`xl/worksheets/sheet1.xml`）。列数 16，比程序输出多一列 `source_file`。
  程序侧 `procedures/spurious_procedure.py::start_csv_stream` 只写 15 列、不含 `source_file`，且**从不合并文件** → 该文件由外部脚本生成。
- 75 行数据 = 74 行（来自 `spurious_stream_20260912_175619.csv`）+ 1 行（来自 `spurious_stream_20260912_195102.csv`，该文件现已不存在）。
- `spurious_stream_20260912_175619.csv` 共 227 行，其中 **153 行是垃圾行**（`amplitude_dbm = 9.91e+37`，R&S 无效值哨兵；`frequency_hz` 为负，如 -919 MHz），
  全部落在 `far_-0.5 ~ far_-0.0GHz`（119 行）与 `far_0.0 ~ far_0.3GHz`（34 行）。清洗脚本只删了这 153 行垃圾，有效行一行没丢。
- 程序侧根因：`_build_far_segment_centers` 的 `start = CF - coverage/2 + span/2`，低载波（<coverage/2）时生成 **≤0 Hz 的段中心**；
  `set_center_frequency` 照样下发负频率 → 仪器返回 9.91e37 无效值 → `_refine_candidate` 只比对噪声底、不校验幅度量级 →
  `_validate_candidate` 各项校验"全过"（因为全是同一个哨兵值，range=0）→ 被标成 **"已确认"** 写入 CSV。
- 垃圾行比例（`output/` 全部杂散 CSV）：
  - `spurious_stream_20260910_095728.csv` 500 行 / 356 垃圾（71%），载波 1–50 MHz，垃圾全在 `far_-0.5GHz`
  - `spurious_stream_20260912_175619.csv` 227 行 / 153 垃圾（67%），载波 10–1000 MHz
  - `MMGspurious_stream_20260909_163249.csv`（419）、`SMBspurious_stream_20260909_111751.csv`（598）、`杂散测量_20260904_143452.csv`（22）：**0 垃圾**（都是 1–40 GHz 高频载波，段中心不会为负）
- 另有两处"真的少了"：`spurious_stream_20260912_195102.csv` 全盘不存在（被删/移走）；`spurious_stream_20260910_095446.csv` / `_095640.csv` 只有表头、0 行（运行中断）。

已修复：
- `procedures/spurious_procedure.py::_build_far_segment_centers()`：跳过中心 ≤0 或低于 `min_frequency_hz` 的远段，避免把频谱仪设到负/过低中心频率。
- `_is_valid_measurement()`：新增静态校验，频率非正、`amplitude_dbm` 为非有限值、绝对值 >200 dBm 或低于 `min_frequency_hz` 均判无效。
- `_measure_carrier()`、`_refine_candidate()`、`_measure_harmonics()`：对仪器返回的功率/频点调用 `_is_valid_measurement()`，无效即跳过并打印提示。
- 调用 `_build_far_segment_centers()` 时传入 `config["min_frequency_hz"]`（默认 9 kHz）。
- 修改后 `py_compile` 通过；用复现脚本验证了低载波下负中心段被正确跳过。
